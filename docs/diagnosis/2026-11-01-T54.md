# vedio-split-view 10-31 起约 30 小时 502：应用静默退出 + 自动重启命令指向错误 launchd 域（Bootstrap fail

> 工单 T54 · vedio-split-view · 2026-11-01 17:59 · agent-tag 只读诊断

## 根因（按影响排序）

1. **应用进程静默退出，源站不可达 → 502**。日志最后一条是 `2026-10-31 11:09:53 GET /api/docs-data → 200 (1ms)`，之后直接跳到 `2026-11-01 17:02:01 → 200 (82ms)`，中间近 30 小时没有任何 error 或退出日志（log_error_lines=0）。进程异常退出完全未留痕，与 T40 同一现象。
2. **自动重启命令损坏：`rc=1 Bootstrap failed: 125: Domain does not support specified action`**。supervisor 显示 plist `com.koven.vsplit.web` 实际加载在 **user/501 的 Background 会话**，而重启命令对 **gui/501** 域做 bootstrap（GUI 域不支持从 SSH/守护进程上下文 bootstrap）。10-31 11:17（runner）与 11-01 01:07（owner 手动）两次重启都同样失败，5 分钟内未恢复 → 无人自愈约 30 小时（与 T49 同一根因）。
3. **平台未对「重启命令失败」本身告警**，只盯探针 down，所以自愈动作失效了 30 小时都没人发现（T49 已提）。

## 影响

- 10-31 11:11 ~ 11-01 17:02 约 30 小时 HTTP 502（S1 down）。
- 近 48h 可用性 37.65%、探针错误率 62.86%、p95 3500ms，全部由本次宕机主导。
- 11-01 17:02 人工拉起后 17:03 冷启动 degraded（0.6），17:04 恢复（T49 冷启动教训复现）。

## 排除了什么

- 不是公网隧道/链路慢：当前公网健康地址 code=200，connect 0.18s / tls 0.37–0.6s / ttfb 0.76–1.0s，在阈值内。
- 不是 DB 问题：`users=2 videos=56 tasks=56` 数据在，DB mtime 持续更新。
- 没有 OOM 直接证据：macOS 无 oom 记录；主机 swap 用 5.7/7.2GB、内存空闲 49%（偏高，列为残余风险，未证实是本次宕机原因）。

## 现在还有没有隐患（有）

- **重启命令仍是坏的**（01:07 今天还失败）：进程再挂一次，又会是几十小时 502。
- **进程仍无退出原因日志/看门狗**：再挂还是查不到死因（T40 未闭环）。
- 主机 swap 5.7GB 偏高，内存压力需持续关注。

## 修复方案

### A. 修复自动重启命令的 launchd 域

重启脚本改为对 plist 实际加载的 user/501 域操作：已加载的 service 用 `launchctl kickstart -k user/501/com.koven.vsplit.web`，未加载时先 `launchctl bootstrap user/501 ~/Library/LaunchAgents/com.koven.vsplit.web.plist`，不要再对 gui/501 做 bootstrap。验收：在 SSH 会话里执行一次重启命令，进程 30 秒内拉起、http://localhost:5180 与 8080 health OK，输出无 Bootstrap failed: 125。

### B. 加 KeepAlive 与退出原因落日志

在 com.koven.vsplit.web.plist 加 KeepAlive=true 让 launchd 自动拉起；在 multi_listen.py 入口注册信号/异常处理，把退出码与 traceback 写入日志。验收：kill 掉进程后 launchd 自动拉起；人为制造一次异常退出，日志里能看到退出原因。

### C. 重启命令失败本身触发告警

让重启命令失败（rc!=0，含 Bootstrap failed）时输出可识别标记并让监控据此产生告警，而不是只等探针 down。验收：人为触发一次失败重启，告警流里出现「重启失败」事件。
