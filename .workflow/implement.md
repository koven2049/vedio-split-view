## 技术栈
按子工程而异（Python / Node 混合）。各子工程自带 `manage.sh` 和依赖声明。

## 验证命令（零退出码才算过）
<!-- 各子工程不统一，在子工程自己的文档里补。通用形态： -->
```bash
lint && typecheck && test && build
```

**部署后关停本地服务。** 验证期间起的本地服务（`manage.sh start` 起的进程、调试
server、watch 进程）在部署完成、线上验证回报之后原则上关掉（`./manage.sh stop`）——
生产端已接管，本地常驻只占端口与内存。唯一例外：还有等用户确认的事项（视觉核对 /
交互走查 / 待演示）则保留，回报时说明保留原因，确认完即关。

## 代码风格
注释仅"WHY 非显然"才写。错误处理分层，不吞错。

## 文档
README 只交代用途——这是什么、解决什么问题，几行说清。不写长篇用法：
参数 / 示例 / 排错另开文档或指向 `manage.sh --help`。

**落地文件写作。** 凡写入 .md / .html / .pdf 等交付物文件，按终稿标准写：读者是没参与过本次
讨论的第三方——只写最终结论与方案，不写讨论过程、备选与修改痕迹，禁止对话指涉
（"我们刚才" / "如前所述" / "你提到的"）。行文有 AI 腔（套话 / 夸张强调 / 排比堆叠 /
破折号癖）时走 `humanizer` skill 清洗，只改表述不改内容。成文后自检一遍，删掉任何
"像在跟人聊天"的句子；内部状态 / 记忆类文件（documentation.md、STATE.md、执行日志）
不算交付物。本条只约束落地文件，对话回复语气不受限。

harness 通用层（AGENTS.md 与 `.workflow/` 的约束、设计类文档）不写具体
工程名——机制是通用契约，绑工程名即硬编码过期源；工程状态归各工程自己
的文档，机器拓扑归 environment.md，登记类文件（如 security.md 审计表）除外。

## 工程状态文档（各工程 `.workflow/documentation.md`）
活跃层：只留当前进度 / 活跃问题 / 最近 3 个动作，≤100 行，越短越健康；
里程碑完成、问题解决立即折叠删除（历史在 git commit 里）。
唯一例外「决策与失败教训」区：APPEND ONLY 只增不删，格式 `日期 — 现象 / 根因 / 铁律`，
失败的尝试必须写；新会话只读最近 2~3 条，找历史用 grep。

## 禁止区域
生产配置文件（`config/deploy.cfg`、`config/env`）、`.venv/`、各子工程 `data/`、`run/`。

## 子 agent 使用
能用就用：调研（多源 / 批量读取 / 搜索 / 长输出）与实施（独立模块开发、修复）都默认派，
独立任务单条消息并发 spawn、长任务后台跑，主 session 不干等；
方案选择权与 commit 收口不下放。
派单四件套：目标（做什么、止于哪里）/ 输出格式（回什么）/ 工具与路径指引
（用哪些命令、读哪些文件）/ 边界（禁碰什么），并附带 effort 配额（预计调用 /
轮次 / 时长上限）——模糊派单 = 重复劳动或漏活，无配额 = 小任务过度投入；
规模随任务走，一句话能说清的小派单直说，不套模板。
并行只切在决策边界：并行单元间不得有隐式决策交叉（文件边界 / 独立调研
方向），有依赖或共享取舍就串行。
等待期不空转——即上文「不干等」的具体动作：先做文件不相交、不依赖在跑
结果的活；结果分批回来分批裁决，不等全齐；禁止动在跑子 agent 的文件范围。
长产出落盘：子 agent 把报告 / 数据 / 长清单写到仓库外（如 /tmp）或派单指定
路径，回传路径 + 摘要，不落 worktree、不把全文灌进对话（防转述失真，
省主 session 上下文）。
写代码不自开 worktree，共享主 session **按任务层规则所在的** worktree——主
session 的开发任务未开 worktree 时，先按 branch-worktree-rules 开再派单，子
agent 模式不豁免任务层（两份规则分层不冲突：那份管「任务在哪干」，本节管
「子 agent 在任务内怎么干」）。共享防线：一文件一写者、不切分支、改动留
工作区由主 session 统一 commit、环境命令（install / sync / rebuild）主 session
串行一次。要切分支 / 换基线 / 干净目录部署才开新 worktree（按
branch-worktree-rules 补配置并计入清理）。
派单提示词自包含——子 agent 不继承本文件上下文，红线与验证命令写进派单。

> 与「探索先行」不冲突：graph 是**定位**手段，sub-agent 是**执行**
> 载体。子 agent 内部同样先用 graph。
