# spec.md — 目标与边界（冻结层）

```
作用：钉死这次任务的目标、范围、约束，防止需求越写越飘。
写入时机：任务启动时由 init/plan 阶段生成；中途变更必须先改它再改代码。
读取时机：每个里程碑开始前由 AI 读一次，作为"什么算对"的依据。
```

---

## 1. 任务标题
<一句话能让陌生人理解这次要做什么>

## 2. 目标（Goal）
- **业务目标**：解决什么用户/业务问题
- **可观察的成功**：完成后，从外部看到的差别是什么（不要写实现细节）

## 3. 范围边界
### 3.1 In Scope
- [ ] 必须做的事
- [ ] 必须做的事

### 3.2 Out of Scope（显式排除）
- 故意不做的事 + 原因
- 故意不做的事 + 原因

> Out of Scope 比 In Scope 更重要——它阻止 AI 顺手扩范围。

## 4. 约束（Constraints）
- **技术约束**：必须用 / 不能用的库、版本、模式
- **数据约束**：兼容、迁移、回滚要求
- **性能约束**：延迟、吞吐、资源上限（给具体数字）
- **合规/安全**：审计、加密、PII 处理要求

## 5. 验收标准（Acceptance Criteria）
列出**可机器验证**的断言。每条必须能写成测试或命令：

- [ ] `pytest tests/test_X.py::test_Y` 通过
- [ ] `curl /api/Z` 在 P99 < 200ms
- [ ] `migration up` 后 `count(*)` 与迁移前一致

> 如果某条标准只能"人眼判断"，把它再拆细，直到能用命令验证。

## 6. 未决问题（Open Questions）
- [ ] 需要确认的事（**问而不是猜**）
- [ ] 需要确认的事

> 所有 Open Questions 必须在进入 `plan.md` 前解决，否则计划会错位。
